# 数据中台（newsplatform）运行手册

> 面向两类读者：**想跑起来看一眼的人**，和**想知道为什么这么设计的人**。
> 命令都可直接复制执行（Windows / Git Bash 环境）。

---

## 一、这套东西是什么

```
                 ┌──────────────────────────────┐
   newsagg       │  powernews（采集库）          │
   采集层  ──────▶│  articles / sources /         │
   (Scrapy)      │  provinces / crawl_jobs ...   │
                 └──────────────┬───────────────┘
                                │ 只读
                 ┌──────────────▼───────────────┐
   newsplatform  │  FastAPI 数据中台             │
   管控层  ◀─────▶│  31 个端点 / Bearer+scope     │
                 └──────────────┬───────────────┘
                                │ 可写
                 ┌──────────────▼───────────────┐
                 │  powernews_platform（中台库） │
                 │  api_keys / audit_logs /      │
                 │  stats_snapshots              │
                 └──────────────────────────────┘
```

**为什么是两个库而不是一个**

- 采集库的写入方**永远是 `newsagg`**，中台对它只读——避免两套代码争抢同一批行；
  唯一例外是 `sources` 的**配置列**（运维改 `enabled` 不必登服务器）。
- 中台自己的状态（API Key、审计、快照）放 `powernews_platform`。
- 两个库的可用性 SLA 不同：采集库挂了应只退化为"文章接口不可用"，
  而中台的鉴权与审计必须还活着。物理隔离才能做到这一点。

## 二、依赖准备

```bash
# 1) Python 依赖（采集层 + 中台层）
pip install -r requirements.txt -r newsplatform/requirements.txt

# 2) MySQL：建两个库并执行 DDL
mysql -u root -p < sql/schema.sql            # powernews（采集库）
mysql -u root -p < sql/platform_schema.sql   # powernews_platform（中台库）

# 3) Redis：本项目内置 redis-server（默认走 6380，因为本机 6379 被 Memurai 占用
#    且不支持 Redis Stream 的 XADD/XREADGROUP）
.redis/redis-server.exe --port 6380 --dir .redis --save "" --appendonly no
```

## 三、配置（全部走环境变量 / `.env`）

`.env` 由 `.env.example` 复制而来，**不入版本库**。中台相关变量：

| 变量 | 说明 |
| --- | --- |
| `POWERNEWS_PLATFORM_DATABASE_URL` | 中台库（可写）。口令不要写进源码 |
| `POWERNEWS_PLATFORM_COLLECTOR_DATABASE_URL` | 采集库（只读）。**必须显式配置**，否则会回落到源码里的 `CHANGE_ME` 占位口令 → 采集库认证失败 |
| `POWERNEWS_PLATFORM_REDIS_URL` | 中台缓存库（默认 `redis://127.0.0.1:6380/1`） |
| `POWERNEWS_PLATFORM_BOOTSTRAP_ADMIN_TOKEN` | 引导令牌，**仅当库内尚无任何 API Key 时**可用，用于初始化第一把 Key。留空即禁用 |
| `POWERNEWS_PLATFORM_SECRET_KEY` | 生产环境务必覆盖 |
| `POWERNEWS_PLATFORM_DEBUG` | `true` 时 `/docs` 开放且异常回显细节；生产置 `false` |

## 四、启动

```bash
# 方式一：模块入口
python -m newsplatform.main

# 方式二：uvicorn 直接指对象
python -m uvicorn newsplatform.main:app --host 127.0.0.1 --port 8000

# 方式三：开发热重载
POWERNEWS_PLATFORM_DEBUG=true python -m newsplatform.main
```

启动日志会给出一份**脱敏后**的配置摘要，并把三个依赖的探活结果打出来：

```
[INFO] powernews.platform.app:   配置 platform_db = mysql+aiomysql://powernews:***@127.0.0.1:3306/powernews_platform
[INFO] powernews.platform.app:   配置 collector_db = mysql+aiomysql://powernews:***@127.0.0.1:3306/powernews
[INFO] powernews.platform.app: 依赖探活: 平台库=ok 采集库=ok Redis=ok
```

> **探活不阻塞启动**：采集库挂了平台仍要能提供鉴权与审计，
> 此时 `/health` 会返回 `degraded`（HTTP 200）而不是 `ok`，
> 平台库挂了才返回 `503`。

## 五、鉴权初始化（首次使用必看）

所有业务接口都要 `Authorization: Bearer <key>`。首次启动时库内没有 Key，
用**引导令牌**创建第一把：

```bash
# 1) 用引导令牌创建一把 admin Key（明文只在这一次返回，请立即保存）
curl -X POST http://127.0.0.1:8123/api/v1/admin/api-keys \
  -H "Authorization: Bearer bootstrap-dev-token" \
  -H "Content-Type: application/json" \
  -d '{"name":"ops-admin","scopes":"admin"}'
# => {"code":0,"data":{"id":1,"name":"ops-admin","key":"pn_xxxxx...","scopes":"admin"}}

# 2) 之后一律用正式 Key
curl http://127.0.0.1:8123/api/v1/articles?page_size=5 \
  -H "Authorization: Bearer pn_xxxxx..."

# 3) 给只读场景单独发一把最小权限 Key
curl -X POST http://127.0.0.1:8123/api/v1/admin/api-keys \
  -H "Authorization: Bearer pn_xxxxx..." \
  -H "Content-Type: application/json" \
  -d '{"name":"dashboard-ro","scopes":"articles:read,stats:read"}'
```

**权限范围（scope）**

| scope | 覆盖 |
| --- | --- |
| `articles:read` | 文章、省份接口 |
| `sources:read` | 来源读取 |
| `sources:write` | 来源新增 / 改配置 / 启停 / 删除 |
| `stats:read` | 统计看板接口 |
| `admin` | 隐含以上全部 + API Key 与审计日志管理 |

> 引导令牌在库内已有 Key 后**自动失效**（这是设计如此，不是 bug）。
> 需要重新引导时：`DELETE FROM powernews_platform.api_keys;`

## 六、响应约定

**成功**（HTTP 200）：

```json
{ "code": 0, "data": { "...": "..." }, "request_id": "6fede1d0fd8240b1aa112715fddd1525" }
```

**失败**：

```json
{ "code": 2001, "detail": "缺少 Bearer Token（Authorization: Bearer <key>）", "request_id": "..." }
```

**业务错误码分段**

| 段 | 含义 | 例 |
| --- | --- | --- |
| `0` | 成功 | — |
| `1000+` | 请求参数类 | `1001` 校验失败、`1002` 数据超出字段范围 |
| `2000+` | 鉴权类 | `2001` 未认证、`2002` 无权限 |
| `3000+` | 资源不存在 | `3001` 通用、`3002` 来源、`3003` 文章、`3004` 省份 |
| `4001` | 冲突 | 唯一键重复、来源下有文章不能删 |
| `4290` | 限流 | 超过 `rate_limit_per_minute` |
| `5000+` | 服务端 | `5000` 内部错误、`5001` 上游不可用 |

> **`request_id` 是排障入口**：响应里带了它，日志里按它 grep 就能拿到完整链路。

### 7.1 `province` 参数怎么写都行

接口面**不要求**你记 6 位行政区划代码。以下写法等价：

| 写法 | 例子 | 结果 |
| --- | --- | --- |
| 6 位代码 | `?province=440000` | 广东省 |
| 全称 | `?province=广东省` | 广东省 |
| 简称 | `?province=广东` / `?province=粤` | 广东省 |
| 大区 | `?province=华南` | 广东 + 广西 + 海南（一次查多省） |
| 特别区域 | `?province=港澳台` | 台湾 + 香港 + 澳门 |
| 不过滤 | `?province=全国` / `all` / `*` / `-` | 全部 |

容错细节：后缀可省可带（`广西` = `广西省` = `广西壮族自治区`）、内部空白会忽略（`广 东`）、
常见错字也收（`新彊`）、`内蒙` 自动补成内蒙古。

> **解析不出来会 400，不会静默返空。** 错误消息里直接列出全部可用取值，
> 例如 `无法识别的省份：米国。可用取值：6 位代码（440000）、全称（广东省）…`

> `/provinces/{code}`（单省详情）**不接**大区名：`/provinces/华南` 会返回 400
> 并列出候选代码，而不是随便挑一个省——静默挑一个会让你以为查对了。

实现见 `newsplatform/core/provinces.py`；解析规则的单测见
`tests/test_province_name_resolution.py`（不需要数据库）。

交互式文档：启动后访问 **`/docs`**（Swagger UI）或 `/redoc`。

## 八、验证（四条命令）

```bash
# 1) 静态检查
ruff check .

# 2) 单元/回归测试：不需要数据库，任何机器都能跑
pytest tests -q
# => 126 passed

# 3) 端到端冒烟：对着真实运行的服务 + 两个库跑 65 项（纯 HTTP，只测中台接口）
python scripts/e2e_smoke.py --write
# => PASS 65 / FAIL 0

#   --write      额外验证来源写接口（创建的临时来源会自动清理）
#   --token pn_xxx   直接复用已有 Key（否则先读本地缓存，再退到引导令牌）

# 4) 市场行情采集链路：真实网络 + 真实采集库（不经中台，链路不同所以脚本分开）
python scripts/verify_market.py --periods 4
# => PASS 62 / FAIL 0

#   --offline    跳过联网，只验库里已有数据（不需要外网）
```

> 用**项目 venv** 跑（`.workbuddy/binaries/python/envs/powernews`），不要用系统 Python：
> 两边 SQLAlchemy / aiomysql 版本不同，系统环境可能缺 `pytest-asyncio`。

冒烟脚本会覆盖：服务可达性、鉴权与错误码、文章四个端点、省份四个端点、
**按省份名称/大区/全国查询共 18 项**、统计八个端点、来源读写七个端点、
管理六个端点，以及**越界入参必须返回 4xx 而不是 500**。

`verify_market.py` 覆盖：五个采集器能否真的从网上抓到、跨数据集不变式
（唯一键无重复、日期不落在未来、量级合理）、**幂等**（二次入库必须全部「未变」）、
值变化时判为「更新」且行数不增、`lng_quote` 明细与 `lng_spot` 汇总能**独立重算对齐**、
以及 `market-stats` 用的那些查询能读回数据。

> **两个脚本为什么要分开**：`e2e_smoke.py` 只 import `httpx`，验的是「上线形态的
> 接口」；市场行情走的是「采集器直连对方站点 → 写采集库」这条完全不同的链路，
> 失败模式是「站点改版 / 风控拦截」而不是「接口挂」。混在一起会让两边都难维护。

## 九、排障速查

| 症状 | 根因 | 处理 |
| --- | --- | --- |
| 启动探活全 `ok`，一请求就 500 | `pool_pre_ping` 触发 aiomysql `ping()` 签名不匹配 | 已由 `newsplatform/core/database.py` 的 `do_ping` 补丁修掉；若被删掉会复现，见 `tests/test_platform_regressions.py` |
| `/health` 返回 `degraded` | 采集库或 Redis 挂了（单点降级，不影响鉴权/审计） | 查对应依赖；Redis 挂只丢缓存，接口**放行**而非拒绝 |
| 采集库认证失败 | `.env` 漏配 `POWERNEWS_PLATFORM_COLLECTOR_DATABASE_URL`，回落到 `CHANGE_ME` | 补上该变量 |
| 写接口返回 200 但库里没数据 | 用了只读会话（退出不提交） | 写路由必须用 `CollectorWriteSessionDep`；提交由 `SourceService` 负责 |
| `Table 'powernews.stats_snapshots' doesn't exist` | 拿采集库会话写了中台库的表 | `StatsService` 必须传 `platform_session=` |
| `Unknown column 'content'` | 正文字段名是 `body_text`（与 `sql/schema.sql` 一致） | 改字段名 |
| `1264 Out of range value` | 接口边界宽于 DDL 列类型（如 `TINYINT` 上限 127） | 对齐 `Field(le=...)`；全局 `DataError` 处理器会把它变成 422 |
| 引导令牌提示"已失效" | 库内已有 API Key（设计如此） | 用正式 Key，或清空 `api_keys` 表后重新引导 |
| 传了筛选参数但结果没变化 | **FastAPI 会静默忽略未知 query 参数**——参数名写错不会报错，只会「看起来没生效」 | 先拿一个**绝不可能命中**的值试（如 `?q=zzzznotexist`）：返回 0 条才算参数接上了。本轮就靠这招发现 `/articles?q=` 被忽略（当时只认 `keyword`），现已互为别名 |

## 十、设计笔记（为什么这么写）

1. **统一响应体 + 稳定业务码**：前端与告警规则只认 `code`，不解析 HTTP 状态之外的语义。
2. **三层异常处理**：`AppError`（业务）→ `HTTPException`（HTTP 语义）→
   `RequestValidationError`（422）→ `Exception`（兜底，**不回显内部细节**）。
   生产环境把堆栈/表名/SQL 回给客户端等于免费送攻击面，细节只进日志。
3. **审计用上下文管理器而不是装饰器**：需要拿到**最终状态码**才能如实记录失败，
   装饰器拿不到。写操作无论成功失败都留痕。
4. **Redis 降级为"放行"而非"拒绝"**：缓存/限流不可用时接口仍要能服务，
   只是慢一点、限流失效——可用性优先于限流强度。
5. **两条关键路径的提交点放在服务层**：保证提交发生在 `audit_write` 作用域内，
   否则审计日志会先写成"成功"，一旦提交失败，日志与事实相反。
6. **`pool_pre_ping` 保留开启**：不靠关掉它来绕过驱动 bug，而是把方言补丁显式写出来，
   让 stale connection 防护继续生效。

## 十一、市场行情采集（LNG 现价 / 上海挂牌 / 电煤指数 / 电力现货价）

与新闻采集并列的**第二类数据源**：结构化时间序列指标，落在采集库
`powernews.market_prices`，由 `newsagg` 独占写。

### 11.1 数据源与口径

| 数据集 | 指标 | 来源（source） | 频率 | 入口 |
| --- | --- | --- | --- | --- |
| `lng_spot` | CLP 分区域 LNG 出厂价（25 个区域） | `cqpgx` 重庆石油天然气交易中心 | 日 | `chinacqpgx.com/cyl?type=1&dt=YYYY-MM-DD` |
| `lng_spot` | 生意社基准价 / 企业报价最高·最低·均价 | `100ppi` 生意社 | 日 | `trq.100ppi.com/news/list---1.html` |
| `lng_spot` | 挂牌汇总：全部/接收站 的 均价·最高·最低 | `shpgx` 上海石油天然气交易中心 | 日 | `POST shpgx.com/eplatform/lngdata/report/listHis` |
| `lng_quote` | 挂牌明细：按交货点 × 销售地逐条报价 | `shpgx` 上海石油天然气交易中心 | 日 | 同上（同一次请求产出，明细入库） |
| `lng_signal` | 均差（10日均线 − 20日均线，**可为负**） | `100ppi` 生意社 | 日 | `trq.100ppi.com/news/list---1.html` |
| `ceci_import` | 进口指数综合到岸标煤单价 | `cec` 中电联 | 周 | `pjzx.cec.org.cn/ms-mcms/mcms/content/detail?id=` |
| `ceci_pmi` | 电煤采购经理人指数 | `cec` 中电联 | 周 | 同上（同一份周报） |
| `power_spot` | 南方区域现货均价：区域整体 / 分省区 / 分电源 | `gzpec` 广州电力交易中心 | 周 | `www.gzpec.cn/news/scyj/` |

> `lng_spot` 有**三个来源**，这不是疏漏：`uk_market_point` 把 `source` 并进唯一键，
> 就是为了让同一指标的多家机构口径各自成行、互不覆盖，便于交叉验证
> （重庆 CLP 的广东价 / 生意社全国基准价 / 上海挂牌均价，三方对照）。

`lng_quote` 与 `lng_spot` 的关系是**明细与汇总**，由 `SHFGXFetcher` 一次请求同时产出：
逐条落 `lng_quote`（`region` = 销售地，`grade` = **交货点/接收站名**），
再按口径汇总出 `lng_spot` 的 `挂牌·全部均价` / `挂牌·接收站均价` / 最高 / 最低。
要问「宁波接收站今天报多少」查 `lng_quote`；要问「今天市场什么水平」查 `lng_spot`。
汇总能随时从明细重算，所以**明细必须留着**——这也是 `verify_market.py` 会拿明细
独立重算一遍去对汇总的原因。

### 11.2 命令

```bash
# 抓最近 1 期（默认，五个采集器各一次）
powernews market-fetch

# 各抓最近 4 期（LNG 按天、CECI/现货按周）
powernews market-fetch --periods 4

# 只抓某个数据集
powernews market-fetch --dataset power_spot --periods 8

# 只想看上海的挂牌明细（75 条/3 天）
powernews market-fetch --dataset lng_quote --periods 3

# 只想看上海的挂牌汇总（接收站均价/最高/最低，6 条/天）
powernews market-fetch --dataset lng_spot --periods 3

# 只抓不写库（不需要 MySQL），用来快速确认「站点还能不能抓」
powernews market-fetch --dry-run

# 覆盖情况汇总
powernews market-stats

# 最新明细
powernews market-stats --dataset lng_spot --latest 14
powernews market-stats --dataset lng_quote --latest 20
```

> `--dataset lng_spot` 会跑 **CLP + 生意社 + 上海挂牌三家**采集器（`lng_spot` 有三个来源），
> 但只写 `lng_spot` 的点。想要「上海的明细 + 汇总」一起入库，用 `--dataset all`。
> 这个"跑哪些采集器"是按 `newsagg/market/fetchers/__init__.py` 的 `PRODUCED_DATASETS`
> 算的，不是按 dataset → 类的单值登记表——后者只会跑 `CLPFetcher`，把另外两家
> **静默漏掉**（命令返回 0、日志全绿，只有翻库才发现）。

### 11.3 业务日期约定（**最容易搞错的一点**）

`price_date` 是**数据所属日期**，不是采集时间，也不是文章发布日：

| 数据集 | `price_date` 取什么 | 为什么 |
| --- | --- | --- |
| `lng_spot`（CLP） | 价格表的 `data-dt` | 页面自报 |
| `lng_spot` / `lng_signal`（生意社） | URL 里的 `detail-YYYYMMDD-` | **标题只写月日不写年**，URL 才带年 |
| `lng_spot` / `lng_quote`（上海挂牌） | 明细行自带的 `startDate` | 上游字段；**解析不出来就丢弃该行，不回落到"今天"**——回落会因唯一键命中而静默覆盖真实值 |
| `ceci_import` / `ceci_pmi` | 正文「本周（X月Y日至A月B日）」的**结束日** | 描述的是「截至 B 日这一周」；用发布日会错位约 4 天 |
| `power_spot` | 标题「（YYYY年M月D日-M月D日）」的**结束日** | 同 CECI |

> 上海挂牌**不是每个自然日都有**：实测 2026-10-10（周六）整天没有记录，
> 相邻的 10-09 与 10-11 都有。所以 `SHFGXFetcher.fetch(days=N)` 取的是
> 「最近 N 个**有数据**的日期」而不是「最近 N 个自然日」——
> 与 `CLPFetcher` 取「最近 N 个可交易日」的口径一致。

### 11.4 排障速查（市场行情）

| 症状 | 根因 | 处理 |
| --- | --- | --- |
| CLP 报「未找到 CLP 价格表（id=priceTbl）」 | `/cyl` **不带 `dt`** 返回的是「日期列表页」，不是价格表（Thymeleaf 同一 URL 两种模板） | `CLPFetcher.fetch()` 已做两段式：先取列表页拿最新日期，再带 `dt` 抓表。别改回一段式 |
| 生意社返回 660 字节、正文是「正在进行安全检查」 | `HW_CHECK` 前端校验 | `PPIFetcher._get` 已自动解析 cookie 名与值后重放。若仍失败会**报错**而不是返回占位页 |
| 南方现货解析不到 `元/兆瓦时` | TRS 编辑器把 `306` / `元` / `/` / `兆瓦时` 拆进了不同 `<font>` | `_strip()` 先剥全部标签再正则；**不要**改成按标签块逐段取文本 |
| `gzpec.cn` 连不上 / `http=000` | 证书链不完整；裸域 `gzpec.cn` 还会被本机代理拦成 502 | 固定走 `http://www.gzpec.cn` + `verify=False`（见 `power_gzpec.py` 的 `_VERIFY_TLS`） |
| 中电联官网 curl 只回 5 KB | `pjzx.cec.org.cn/detail/index.html` 是纯 JS 壳，正文靠 `index.js` 里的 `$.get` 拉 | 直接打站内 JSON 接口 `/ms-mcms/mcms/content/detail?id=`，**不要**去解析壳页 |
| 上海挂牌接口 404 | 照着首页 `<table data-ajax-url="/exdata/pngexchangedata/pagelist.json">` 写——**那条是死链**（nginx 404）。真正在用的是 `/eplatform/lngdata/report/listHis` | 见 `lng_shpgx.py` 模块 docstring；别信 `data-ajax-url` |
| 上海挂牌均价莫名偏低几十元 | 用了 `listAll` 而不是 `listHis`。`listAll` 含 `price=null` 的「暂不报价」行（实测 2026-10-11：29 行 vs 25 行） | 只用 `listHis`；`parse_quote_rows` 把 `None` / `""` / `"-"` 一律跳过 |
| 上海挂牌翻页每页只回 500 条 | 服务端单页**硬上限 500**，`length` 给 1000/2000/5000 都只回 500 | 按 `start += len(root)` 翻页直到 `start >= totalProperty` |
| 「接收站均价」偏低 | 「北燃南港」（北京燃气天津南港接收站）名字里**没有**「接收站」三个字，被 `"接收站" in name` 判成液厂 | 用显式白名单 `RECEIVE_STATIONS`，**不要**改成字符串包含 |
| 新增交货点后没进「接收站」口径 | 白名单是显式的，上游加了站不会自动进来 | 先 `powernews market-fetch --dataset lng_quote --dry-run` 看实际交货点取值，再补 `RECEIVE_STATIONS` |
| CECI 进口指数某期缺失 | 假期停发（官网有《国庆节期间暂停发布CECI各指数的公告》） | 只告警不抛错，属预期 |
| 指数值对不上第三方转述 | 第三方常混用「基准价」「企业报价均价」「接收站均价」三个口径 | `raw` 里存了原文标题与样本数，按 `grade` 区分：`生意社基准价` ≠ `企业报价·均价`（后者只是液厂报价样本的算术均值），也 ≠ `挂牌·接收站均价`（上海挂牌里接收站摊位的均值）。见 11.6 |

### 11.5 设计笔记（市场行情）

1. **采集器不碰数据库**：`fetchers/*` 只产出 `MarketPoint`，解析逻辑因此能喂写死
   HTML 单测（不需要 MySQL）。入库在 `store`，编排在 `cli`。
2. **分区分「价格」与「信号」**：`lng_signal` 是价差、天然为负，单独成数据集，
   否则 `AVG(value) GROUP BY dataset` 会被负值污染。`SIGNED_DATASETS` 显式声明这件事。
3. **占位符不等于 0**：行情表里的 `-` / `—` 表示「本期无数据」，一律转 `None`。
   写成 0 会在算涨跌幅时产生假的暴跌。
4. **抛错优于静默空**：解析出 0 条一律抛 `ValueError`。静默返回空会让
   「页面改版」和「今天真的没发布」永远无法区分。
5. **跨年日期按发布日推年份**：CECI 正文明写「12月28日至1月3日」时，结束日属于
   下一年；生意社则更极端——标题根本不写年，只能靠 URL。
6. **幂等由唯一键保证，不靠应用层判断**：`INSERT ... ON DUPLICATE KEY UPDATE`
   一次搞定，`rowcount` 的 1/2/0 三态正好对应「新增/更新/未变」，
   直接拿来当幂等报告。
7. **明细与汇总分开落，明细是母本**：上海挂牌一次请求既有逐条报价也有可推导的
   汇总。只存汇总就丢掉了"换一个口径重算"的能力（比如以后想按公司而不是按站
   分档），所以 `lng_quote` 与 `lng_spot` 都写；`verify_market.py` 还会拿明细
   独立重算一遍去对汇总，确保两边不会悄悄分叉。
8. **`grade` 在不同数据集里承载不同东西**：`lng_spot` 里是规格口径
   （`日前` / `到岸标煤单价` / `挂牌·接收站均价`），`lng_quote` 里是**交货点**
   （`宁波接收站`）。这不是随意复用——唯一键 `(dataset, region, grade, price_date, source)`
   要求同一天同一销售地的多个交货点必须能被区分开，而 `grade` 正是那个区分位。
   两边语义的差异写在 `sql/schema.sql` 的列注释里，改表前先看那行。
9. **「跑哪些采集器」与「写哪些数据集」是两个问题**：前者按
   `PRODUCED_DATASETS`（类的全部产出）算，后者按 `--dataset` 过滤。
   混成一个的代价是 `--dataset lng_spot` 只会跑 CLP，漏掉另外两家**且不报错**。

### 11.6 口径对照：同一句「LNG 现价」可能指三件不同的事

排查「数字对不上」时先看这张表。所有数字都能在库里按 `dataset + grade` 精确定位：

| 转述里的说法 | 库内定位 | 2026-10-09 实测 | 样本 |
| --- | --- | --- | --- |
| 「生意社基准价 6152」 | `lng_spot / CN / 生意社基准价 / source=100ppi` | 6152 元/吨 | 生意社自己的基准价 |
| 「现货价 6230，单日涨 78」 | `lng_spot / CN / 企业报价·均价 / source=100ppi` | 6230 元/吨 | 生意社收录的 **5 家液厂**报价算术均值（6200/6170/6300/6300/6180） |
| 「中海油宁波报价最高 7250」 | `lng_quote / 上海 / 宁波接收站 / source=shpgx` | 7250 元/吨 | 上海石油天然气交易中心**挂牌** |
| 「接收站均价」 | `lng_spot / CN / 挂牌·接收站均价 / source=shpgx` | 6637.33 元/吨（15 个摊位） | 上海挂牌里 8 个接收站的摊位 |
| 「市场均价」 | `lng_spot / CN / 挂牌·全部均价 / source=shpgx` | 6270 元/吨（25 个摊位） | 上海挂牌全部摊位（含山西液厂） |

> **6637.33 而不是 6640**：早先一份草稿用 `"接收站" in name` 判接收站，
> 漏掉「北燃南港」，样本 14 个、均值 6640。用白名单后样本 15 个、均值 6637.33。
> 40 分之一的差异会被误当成"口径不同"，其实是判定漏洞——这就是白名单存在的理由。

**注意**：第三方日报里的「市场均价 6382 / 接收站均价 6731 / 较高 7000 / 较低 6150」
这组数字**抓不到公开来源**——它们不属于上述任何一行。上海挂牌的同日口径是
6270 / 6637.33 / 7250 / 5400，生意社液厂样本是 6230 / 6170 / 6300。
这组数字应来自付费行情商（隆众 / 卓创 / 金联创一类）的日评，
是"含接收站与液厂的加权市场价"这一类自有口径。
**本模块的原则是：没有可公开核对来源的口径不抓**，而不是拿相近的数字凑一个上去。
