## 二、攻克时间线（按发生顺序）

### 1. 阶段二 · 首轮探活

### 2. 阶段七 · 412 攻坚（进行中）

- **卡点现象**：HTTP 返回 412 + 5597 字节响应体，`<script r='m'>` 内定义 `$_ts` 全局变量，为**瑞数信息（RiverSecurity）动态防护**：服务端返回混淆 JS，需浏览器执行后回传 `PW9ydXnjjO8XS` 等 Cookie 才能换取真实页面。
- **排查步骤 / 操作指令**：
  - 抓取 412 响应体，确认含 `$_ts=window['$_ts']` 与 `r='m'` 标记；
  - 用 `chrome-devtools` MCP 打开 `http://www.bj.sgcc.com.cn/`；
  - 检查页面：Cookie `PW9ydXnjjO8XT`（271 字符）成功种上，但页面稳定在 39 字节空白；
  - 执行 JS 读取指纹：`navigator.webdriver=true`、plugins=5、langs=zh-CN,zh。
- **验证结果 / 最终方案**：判定挑战未通过。怀疑 `navigator.webdriver=true` 被瑞数识别为自动化环境。
- **可复用经验**：瑞数防护需真实浏览器完成 JS 挑战并回传 Cookie；纯 requests/httpx 无法伪造。

### 3. 阶段七 · 启动 CDP 真实浏览器

- **卡点现象**：需要绕过 `navigator.webdriver` 检测，且不许用 MCP 默认自动化指纹。
- **排查步骤 / 操作指令**：
  - 启动独立实例：`chrome.exe --remote-debugging-port=9222 --user-data-dir=<tmp> --headless=new --disable-blink-features=AutomationControlled`；
  - 验证 CDP：`GET http://127.0.0.1:9222/json/version` → 200（Chrome/154）；
  - 编写 `scripts/cdp_probe.py`，通过 WebSocket 驱动页面并轮询 DOM/Cookie。
- **验证结果 / 最终方案**：CDP 通道打通，待完成瑞数挑战验证（见任务 #8）。
- **可复用经验**：`--disable-blink-features=AutomationControlled` 可去掉 webdriver 标志，是绕过瑞数自动化检测的关键开关。

### 4. 阶段八 · CDP 真实浏览器攻克瑞数 412

- **卡点现象**：本站点此前受**瑞数动态防护（RiverSecurity）**拦截：HTTP 返回 412，响应体仅 2~6KB 混淆 JS（含 `$_ts` 全局变量与 `<script r='m'>`），纯 httpx 请求无法拿到正文。
- **排查步骤 / 操作指令**：
  - 启动真实 Chrome：`--user-agent=<普通 Chrome UA>` + `--disable-blink-features=AutomationControlled` + `--remote-debugging-port=9222`；
  - 确认 UA **不含** `HeadlessChrome`（headless 默认 UA 会直接暴露），且 `navigator.webdriver=false`；
  - 用 CDP `Page.navigate` 打开列表页，轮询 `document.documentElement.outerHTML.length` 直至挑战通过、DOM 渲染稳定（>2KB 且不再增长）；
  - 取渲染后 HTML 交回**既有适配器** `parse_list` / `parse_detail` 解析（解析逻辑零改动）；
  - 详情页 `<h1>` 为栏目名时，回退使用列表页标题；过滤 PDF/Office 附件链接。
- **验证结果 / 最终方案**：瑞数挑战通过，成功入库：国网北京市电力公司（15 篇）。
- **可复用经验**：瑞数 412 只能靠真实浏览器执行 JS 挑战破解；两个关键开关——UA 去掉 HeadlessChrome、关闭 navigator.webdriver。
