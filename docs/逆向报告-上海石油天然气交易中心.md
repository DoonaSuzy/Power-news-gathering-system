## 1. 方法与取证原则

全部结论来自**可复现的被动/半主动探测**，不做任何凭证构造：

1. **前端源码还原**：下载页面与外链 JS，从 `$.ajax` / `gridpage` 调用点反推全部 API 路径与入参。
2. **错误信息分叉**：服务端对鉴权各分支返回不同 `msg`，于是"改了哪个头/哪个值"能从报文差异读出来。
3. **边界探测**：用极大/极小/畸形入参确认分页上限、日期区间语义、空值行为。
4. **原文留证**：每条结论都对应 `data/reverse-shpgx/jwt_evidence.json` 里的一对请求/响应原文。

> **红线**：不构造有效凭证、不爆破密钥、不尝试登录。token 的**签发侧**属于会员体系，不在本报告范围。

## 3. 前端调用链还原

### 3.1 表格页的通用机制

所有列表页（报价数据 / 出站价格 / 省价格 / 地级市价格 / 液化天然气数据 / 周度价格 / 月度均价）
共用一套前端分页封装，位于 `/js/jquery.mypagination.js`：

```javascript
function gridpage(grid){
    var url     = grid.url;        // 接口路径
    var param   = grid.param;      // 表单序列化结果
    var length  = grid.length;     // 每页条数
    var currentPage = 1;
    params.start  = 0;             // ← 偏移量
    params.length = length;        // ← 页大小
    params.ts     = (new Date()).getTime();   // ← 防缓存时间戳
    $.post(url, params, function(responseText){
        var json = eval(responseText);
        var total = json.totalProperty;   // ← 总条数
        ...
        // 翻页：params.start = (posPage - 1) * length;
    });
}
```

**三个必须复刻的细节**：`start` 是**偏移量不是页码**；`length` 是页大小；`ts` 是毫秒时间戳。
漏掉 `start` 推进会让每页取回同一批数据（本项目里已固化成回归测试）。

### 3.3 两个「死链级」陷阱

**陷阱 A：`data-ajax-url` 是装饰品**

`/html/LNGbjsj.html` 等 8 个页面里写着：

```html
<table id="pngexchangedata-dt"
       data-ajax-url="/exdata/pngexchangedata/pagelist.json" ...>
```

直接请求它 → **`404 nginx/1.30.1`**。真正在跑的是外链 JS 里的 `listHis` / `listAll`。
**照着 HTML 属性写采集器，第一步就是 404。**

**陷阱 B：站点自己在两代接口之间摇摆**

`/html/zgLNGccjgqyzs.html` 内联脚本原文：

```javascript
var url="/marketzhishu/map";
//var url="/eplatform/dataapi/marketzhishu/map";
```

而 `/js/charts/png_1.js`（周度价格页）里的新接口**没有被注释**：

```javascript
gridpage({url:""+"/eplatform/dataapi/marketzhishu/zhishuList", ...});
```

**推论**：`/eplatform/dataapi/*` 是**新的鉴权层**，迁移做了一半——区域指数页退回了旧接口，
周度/月度价格页还在用新接口。后者对**匿名访客是坏的**（拿到 401、表格空白）。

## 5. 鉴权层逆向

### 5.1 鉴权头名：`token`

探测手法是**错误信息分叉**——对一个受保护接口循环替换请求头名：

| 请求头 | 响应 `msg` | 判定 |
| --- | --- | --- |
| *（不带）* | `invalid token` | 缺失分支 |
| `token: Bearer FAKE.JWT.SIG` | `token失效，请重新登录` | **被识别** |
| `Authorization: Bearer FAKE...` | `invalid token` | 不识别 |
| `X-Token: Bearer FAKE...` | `invalid token` | 不识别 |
| `X-Auth-Token: Bearer FAKE...` | `invalid token` | 不识别 |
| `jwt: Bearer FAKE...` | `invalid token` | 不识别 |

大小写实验（`token` / `Token` / `TOKEN` / `tOkEn`）四种拼写得到**同一条 msg** ——
符合 HTTP 头名大小写不敏感的规范。这一条没有工程价值，但能避免后来人
"再测一遍大写"。

**注意**：请求头名是 `token` 而**不是** `Authorization`，值里带不带 `Bearer ` 前缀
服务端都不认（`hello`、`aaa.bbb`、合法三段 JWT 得到的都是同一条 msg）。

### 5.2 两条错误分支

| 分支 | 触发条件 | HTTP | 业务码 | `msg` |
| --- | --- | --- | --- | --- |
| 缺失 | 请求头不存在，或值为**空字符串** | **200** | `401` | `invalid token` |
| 无效 | 头存在且非空（任意内容） | **200** | `401` | `token失效，请重新登录` |

**关键**：HTTP 状态**永远是 200**，鉴权结果只体现在 body 的 `code` 里。
按 HTTP 状态写重试逻辑会永远重试 401。

另：`Bearer FAKE`、`hello`、`aaa.bbb`、合法结构但假签名的 HS256 JWT —— 四者 msg **完全相同**。
说明服务端对「格式不合法」与「签名不通过」**不做区分**（或者干脆没走到格式校验）。
因此**无法从报错反推 token 的算法**。

### 5.3 过滤器边界：先鉴权，后路由

| 探测路径 | 结果 |
| --- | --- |
| `/eplatform/lngdata/report/listHis` | ✅ `success`（**白名单**） |
| `/eplatform/lngdata/report/listAll` | ✅ `success`（**白名单**） |
| `/eplatform/lngdata/report/listXxx`（不存在的子路径） | ❌ 401 `invalid token` |
| `/eplatform/marketzhishu/list/3/22` | ❌ 401 `invalid token` |
| `/eplatform/xxx`（任意未知路径） | ❌ 401 `invalid token` |

**「不存在的子路径」与「存在的受保护路径」返回同一条 401** → 鉴权过滤器在路由**之前**执行。

这带来一个实用结论：**`/eplatform/` 下的端点无法通过状态码/报文差异枚举**。
暴力列举不成立，路径只能从对方前端代码里反推——这也是本报告 §3.2 必须扫外链 JS 的原因。

### 5.4 CORS 配置

| 接口层 | 响应头 |
| --- | --- |
| `/eplatform/lngdata/report/listHis` | `Access-Control-Allow-Origin: *`、`Allow-Methods: GET,POST,OPTIONS`、`Allow-Headers: *`、`Vary: Origin` |
| `/eplatform/dataapi/marketzhishu/map` | `Access-Control-Allow-Credentials: true` + `Access-Control-Allow-Origin: *` |

后者的组合**违反 CORS 规范**（凭证模式下 `*` 不被允许），浏览器会拒绝该响应。
这是数据层从「开放」向「带凭证」迁移留下的痕迹，与「新接口需 token」的判断一致。

## 6. JWT 与 HS256 工具

### 6.1 我们拿到了什么 / 没拿到什么

**拿到了（有原文证据）**：

- 受保护接口要求请求头 **`token`**，缺失/无效两条不同的 msg；
- 鉴权过滤器先于路由；
- 站点前端**确实有生效的** `/eplatform/dataapi/*` 调用（`png_1.js` / `png_2.js`）——
  说明这条路是活的，只是需要登录态；
- 另有**被注释掉的**调用点，说明站点自己也在两代接口间摇摆。

**没拿到（也不打算拿）**：

- **有效 token 本身**。签发侧在会员体系（`kh.shpgx.com` 为 Tomcat 应用、`egas.cnfin.com` 为 E-Gas 终端），
  需要会员账号登录。本报告不涉及登录流程，不做任何凭证构造。
- **算法与密钥**。服务端对各类畸形 token 返回同一条 msg，黑盒无法判定 `alg`；
  且**即便判定出来也没有意义**——密钥不在客户端，且不去爆破。

> 因此 `HS256 解码/验签工具` 的定位是：**给任何你合法持有的 JWT 做解码与验签**，
> 而不是"破解本站 token"。这一点在工具的使用说明与源码里都写死了。

### 6.2 工具：`scripts/jwt_hs256_tool.py`

纯标准库（`hmac` / `hashlib` / `base64` / `json`），支持 HS256 / HS384 / HS512。

```bash
# 解码（不需要密钥）
python scripts/jwt_hs256_tool.py decode <token>
python scripts/jwt_hs256_tool.py decode --file token.txt

# 验签（推荐用环境变量，避免进 shell 历史与进程列表）
python scripts/jwt_hs256_tool.py verify <token> --secret-env JWT_SECRET --alg HS256

# 签发（自用 / 造测试向量）
python scripts/jwt_hs256_tool.py sign --payload '{"sub":"demo"}' --secret s --exp 3600

# 自检（本地往返 + 逐项破坏，不需要网络）
python scripts/jwt_hs256_tool.py selftest
```

**实测**：


### 6.3 工具的防绕过设计（逐条有测试）

| 防护 | 做法 | 回归测试 |
| --- | --- | --- |
| **alg confusion（`none`）** | 声称 `alg: none` 的 token **任何参数下都不通过**；`--allow-none` 只换更明确的说明文字，不改变判定 | `test_alg_none_is_rejected_even_when_explicitly_allowed` |
| **算法拼写变体** | 只认 `HS256`/`HS384`/`HS512` 三种**精确拼写**，拒 `hS256` / `HS256 ` / `hs256` | `test_alg_spelling_variant_is_rejected` |
| **跨算法降级** | 调用方写死期望算法时，token 自称的算法不符即拒 | `test_cross_algorithm_downgrade_is_rejected` |
| **定时比较** | `hmac.compare_digest`，不用 `==`，避免签名被逐字节试探 | （实现层） |
| **不做密钥恢复** | 源码里不存在 wordlist / brute / dictionary 之类入口 | `test_no_secret_recovery_code_path_exists` |
| **段数严格** | 必须三段；两段（`none` 写法之一）或四段（JWE）直接报错，不"猜" | `test_split_token_requires_exactly_three_segments` |

`tests/test_jwt_hs256_tool.py` 共 **26** 例，全绿。

### 7.3 汇总（`..._summary.csv`）

每天 6 个口径：`挂牌·全部均价/最高/最低`、`挂牌·接收站均价/最高/最低`，
另带 `sample_size`（样本数）、`max_of_sample` / `min_of_sample`。

**分两套口径**的理由：山西液厂出厂价与沿海接收站槽批价差着 1000 元量级，
混在一起算出的"均价"没有业务含义。2026-10-09 实测：

| 口径 | 值 | 样本数 |
| --- | --- | --- |
| 全部均价 | 6270.00 | 25 |
| 全部最高 / 最低 | 7250.00 / 5400.00 | 25 |
| 接收站均价 | **6637.33** | **15** |
| 接收站最高 / 最低 | 7250.00 / 6460.00 | 15 |

### 7.4 口径对照（避免"数字对不上"的误判）

同一句「LNG 现价」在这套数据里有**四层不同含义**：

| 说法 | 出处 | 2026-10-09 |
| --- | --- | --- |
| 中海油宁波报价最高 | `lng_quote` 上海 / 宁波接收站 | **7250** |
| 挂牌·接收站均价 | 上海挂牌 8 个接收站的摊位均值 | **6637.33** |
| 挂牌·全部均价 | 上海挂牌全部 25 个摊位均值 | **6270** |
| 生意社基准价 / 企业报价均价 | 生意社（液厂样本，另一来源） | 6152 / 6230 |

**第三方日报常出现的「市场均价 6382 / 接收站均价 6731 / 较高 7000 / 较低 6150」
不属于以上任何一层**，公开源里没有这组数，应来自付费行情商的自有加权口径。
本模块的原则是**不抓、也不用相近数字凑**。

## 8. 坑位速查

| 症状 | 根因 | 处理 |
| --- | --- | --- |
| 请求 `data-ajax-url` 报 404 | 那是**死链** `/exdata/pngexchangedata/pagelist.json` | 用 `listHis` |
| 均价莫名偏低几十元 | 用了 `listAll`（含 `price: null` 的「暂不报价」行） | 只用 `listHis`；`None`/`""`/`"-"` 一律跳过 |
| 每页只回 500 条 | 服务端单页**硬上限 500** | 按 `start += len(root)` 翻页到 `totalProperty` |
| 每页取回同一批数据 | 把 `start` 当页码用了 | `start` 是**偏移量** |
| `--days 1` 拿到空 | 该站点**不是每天都有挂牌**（2026-10-10 没有） | 取「最近 N 个**有数据**的日期」 |
| 接收站均价偏低 | 「北燃南港」名字里没有「接收站」 | 显式白名单，不用字符串包含 |
| 多日环比全是 0 或乱值 | 分组键漏了销售地（宁波接收站在 5 个销售地各报一次） | 键用 `(交货点, 销售地)` |
| 401 却发现 HTTP 是 200 | 业务码在 body 的 `code` 里 | 判 `code`，不判 HTTP 状态 |
| 想枚举 `/eplatform/` 端点 | 过滤器先于路由，未知路径也回同一条 401 | 从前端 JS 反推路径 |
| 拿到 401 `invalid token` | 请求头名写成了 `Authorization` | 头名是 **`token`** |

## 10. 合规与边界声明

1. **只采集公开数据**。所有使用的接口在**无凭证**状态下即返回数据；未绕过任何访问控制。
2. **未尝试取得或破解凭证**。鉴权层的逆向停留在「服务端公开返回的报错信息」层面，
   不含登录流程、凭证构造、密钥爆破。
3. **工具中立**。`jwt_hs256_tool.py` 是通用 JWT 工具，其防绕过设计（拒绝 `alg: none`、
   精确算法匹配、定时比较）是**为了防御**，不是为了攻击；源码中不存在任何密钥恢复能力（有测试钉住）。
4. **保留来源标识**。采集请求携带可识别的 UA 与 `Referer`，不伪装、不改写。
5. **控制频率**。分页顺序请求，无并发轰炸；单次全量采集（5 个月明细）也只需 4 次请求。
